TEST BUILD V15.9.8.1

SDF.R Mac/Linux テスター向けガイド

Windows版をベースに、macOSおよびLinuxに移植した初期動作検証用ビルドです。

1. テストでの検証項目（確認するべきこと）

  • 1
    アドオンのインストールと有効化
    配布されたZIPファイル（そのまま）をBlenderにインストールし、アドオンのチェックボックスをオンにした際、エラーダイアログが出ずに有効化できるか。
  • 2
    エンジン初期化ログの確認
    Blenderのシステムコンソール（またはターミナル）に以下のログが表示されているか。
    SDF.R: --- Initializing GPU Engine (V15.9.8.1) ---
    SDF.R: GPU Engine Ready!
  • 3
    基本メッシュ生成とリアルタイム同期
    SDFメッシュを作成し、球体やボックス等の形状を追加・移動した際、リアルタイムかつ滑らかに変形がビューポートに同期されるか。スムーズ合成の適用時にメッシュ崩れが発生しないか。
  • 4
    解像度設定の耐久テスト
    解像度（Resolution）を128、256などに変更した際、極端な処理フリーズやクラッシュ（Blenderの強制終了）を引き起こさないか。
  • 5
    アドオンの無効化・アンインストール
    アドオンの無効化、および削除がクリーンに完了するか。

2. エラー発生時の自己対処法（よくある問題）

macOS特有：Gatekeeper（実行ブロック）の回避手順 ▼

Actionsで自動ビルドされたmacOS用のバイナリ（rust_gpu_sdf.so）はAppleデジタル署名が無いため、セキュリティ機能「Gatekeeper」によってロードが一時ブロックされます。

【解決手順】

1. ブロックのエラーダイアログが出た場合、一度「キャンセル」を押します。

2. macOS of 「システム設定」＞「プライバシーとセキュリティ」を開きます。

3. 画面の下部に「"rust_gpu_sdf.so" は使用がブロックされました」と表示されているので、「このまま開く」をクリックします。

4. Blenderに戻り、アドオンのチェックボックスを再度オンにします。

Pythonのインポートエラーや循環参照エラー ▼

Blenderがアドオンの一時フォルダ（exec_legacy等）でロードを行う際、モジュールのパッケージ名が正常に解決できず attempted relative import with no known parent package が発生する場合があります。本ビルドではこれらを安全に回避する仕組みを組み込んでいますが、依然としてエラーが出る場合はコンソールログをそのまま開発者へお伝えください。

GPU関連のエラー（Parent device is lost / クラッシュ） ▼

SDF.RはWebGPU（wgpu）エンジンを利用しています。Linux等でグラフィックドライバが古い場合、またはオンボードGPU等で初期化に失敗した場合、初期化ログでフリーズ、またはクラッシュすることがあります。その際はOS名とGPUモデルを添えてお知らせください。

エラーが発生した場合は、以下のテンプレート内の情報をご用意の上、ご報告ください。報告文は下の「コピーする」ボタンでクリップボードにコピーできます。

💡 Blenderのシステムコンソール（ログ）の開き方

macOS / Linux: Blenderをターミナル（Terminal）から起動する必要があります。ターミナルを開き、Blenderのバイナリパス（例: /Applications/Blender.app/Contents/MacOS/Blender）を入力して起動すると、エラーが発生した瞬間のログがリアルタイムにターミナル上に表示されます。
