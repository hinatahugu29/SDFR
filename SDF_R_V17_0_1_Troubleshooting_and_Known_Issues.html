1. 対応環境とOS別の前提条件

対応Blenderバージョン: 推奨 Blender 4.2 LTS / 4.3 / 5.x 系（下限: Blender 3.6 LTS 以上、Python 3.10〜3.13対応）

OSアーキテクチャ状態必須要件・特有の注意点
Windows x86_64 標準パッケージ ・Vulkan 1.2+ または DirectX 12 対応GPU
・最新のGPUディスプレイドライバ
・Visual C++ 再頒布可能パッケージ
macOS Apple Silicon (arm64) テストビルド提供 ・Apple Silicon（M1/M2/M3/M4等）専用。Intel Mac非対応。
・Metalバックエンド。
・Gatekeeper（セキュリティ）警告の回避が必要（下記参照）。
Linux x86_64 テストビルド提供 ・glibc 2.31 以上
・Vulkan対応ドライバ（mesa-vulkan-drivers または NVIDIA公式ドライバ）
・WSL2（Windows Subsystem for Linux）でのGUI動作検証済み。
⚠️ macOSでの重要注意（Gatekeeperブロックの解除手順）:
macOS版のバイナリ（librust_gpu_sdf.dylib）は未署名のため、Blenderでアドオンを有効化しようとした際に「開発元を検証できないため開けません」というセキュリティ警告が出ることがあります。
  1. 警告が出たら一度「キャンセル」をクリックします。
  2. macOSの「システム設定」>「プライバシーとセキュリティ」を開きます。
  3. 画面下部に「librust_gpu_sdf.dylib は開発元を確認できないため使用がブロックされました」と表示されている箇所の 「このまま開く」 をクリックします。
  4. Blenderに戻り、再度アドオンのチェックボックスをONにすると正常に有効化されます。

2. インストール手順と初回起動の重要注意

インストール手順

  1. 配布パッケージZIPファイル（例: SDF_R_V17_0_1.zip 等）を用意します（ZIPを展開・解凍しないでください）。
  2. Blenderを起動し、メニューの 編集 (Edit) > プリファレンス (Preferences) を開きます。
  3. アドオン (Add-ons) タブを選択し、右上の インストール... (Install...) ボタンをクリックします。
  4. ZIPファイルを選択してインストールします。
  5. リストに表示された SDF.R（または Rust-GPU-SDF）にチェックを入れて有効化します。
  6. 3Dビューポートで N キーを押し、サイドバーの SDF.R タブが表示されることを確認します。
⚠️ 超重要: 初回起動時の「ウォームアップ時間（Shaderコンパイル）」について
初めてアドオンを有効化し、Initialize SDF System を実行した直後、またはキャッシュクリア直後は、GPUシェーダー（WGSL）のコンパイルとコンピュートパイプラインの構築がバックグラウンドで実行されます。

この間、Blenderが一見フリーズ・応答停止したように見えますが、内部で正常にコンパイルが進行しています。絶対にBlenderを強制終了しないでください。
  • ディスクリートGPU（NVIDIA GeForce RTX, AMD Radeon 等）: 15秒 〜 45秒程度 で完了します。
  • 内蔵GPU（Intel Iris Xe, UHD Graphics, AMD Radeon 680M/780M 等）: 2分 〜 3分以上（実測194秒など） かかる場合があります。
コンソールでの進行確認: Blenderのメニュー ウィンドウ (Window) > システムコンソール切り替え (Toggle System Console)（Windowsの場合）を開いておくと、Compiling MC Pipeline... → GPU Engine Ready! と進捗ログが確認できます。

3. アップデート・キャッシュ管理の注意点

過去バージョンから更新した場合や、PCのGPU・ディスプレイドライバを更新した直後、Initializing... から進まなくなったり、起動時にクラッシュすることがあります。その場合はシェーダーキャッシュを手動で削除してください。

キャッシュファイルの保存場所:

  • Windows: %APPDATA%\Blender Foundation\Blender\<バージョン>\datafiles\rust_gpu_sdf\shader_cache.bin
  • macOS: ~/Library/Application Support/Blender/<バージョン>/datafiles/rust_gpu_sdf/shader_cache.bin
  • Linux: ~/.config/blender/<バージョン>/datafiles/rust_gpu_sdf/shader_cache.bin
※ キャッシュファイルを削除しても、次回Blender起動時に自動的に最新のキャッシュが再生成されます。

4. 作業中の落とし穴・注意点（SDFモデリング特有）

① プリミティブの順序と「Subtractが効かない」問題

現象: Cylinder を追加して Subtract（くり抜き）にしたのに、穴が開かない。
原因: SDF.Rの The Stack は 「上から下へ」 順番に評価されます。削る対象となる本体（Union）よりもスタックの上（手前）に Subtract を置いても、削るべき形状がまだ存在しないため何も起きません。
対策: The Stack 上で、Subtract プリミティブを削りたい形状より 「下」 に移動（▼ボタン）させてください。

② 意図しないパーツまで削れてしまう「誤爆貫通」

現象: 腕のパーツに開けたネジ穴（Subtract）が、遠く離れた胴体まで突き抜けて削ってしまう。
原因: スタック上で平坦に積まれていると、Subtractは自分より上にあるすべての形状に作用します。
対策: 1. Collection Divider を使う: 腕パーツ群の直前にDividerを置き、グループ化・カプセル化します。
2. マルチツリー（Add Tree） を使う: 胴体と腕を別ツリーとして作成し、Tree Reference で合体させるとブーリアンが完全に分離されます。

③ BBox（バウンディングボックス）の端切れ

現象: 大きく引き伸ばした形状や、大きなSmoothnessで広がった部分の端が、透明な壁にぶつかったようにスパッと平らに切れてしまう。
原因: SDFのGPU計算領域（Bounding Box）の外側に形状がはみ出しているためです。
対策: Output & Quality セクションの BBox Padding（余白倍率）を 1.2 〜 1.5 程度に引き上げるか、Bounding Box Mode を Manual にして手動でボックスを拡大してください。

④ Radial Array（放射状配列）の端が欠ける

現象: Radial Array Count を増やした際、回転角度を大きくするとパーツの端が削ぎ落とされる。
原因: SDF.Rのラジアル配列は空間をピザのような扇形スライス（360° / Count）に折りたたんで計算するため、パーツの大きさがスライスの角度幅（目安 180° / Count）をはみ出すとクリッピングされます。
対策: パーツの回転量を抑える、Count を適切に調整する、または別ツリーとして作成してBlender側のオブジェクト複製で並べてください。

⑤ プレビューの負荷とFPS低下

現象: プリミティブ数が増えると、視点回転や移動が重くなる。
対策: 造形中は Output & Quality の Resolution Preset を Low または Medium に設定してください。また、大量に移動・変形を行う作業中は一時的に Live Update を OFF にし、位置が決まってから Force Update を押す運用が効果的です。

5. V17.0.0 / V17.0.1 特有の既知の問題と制限

① ギズモ未対応（パネル専用）のパラメータ

V17.0.0で多くのパラメータがビューポートギズモに対応しましたが、以下の項目は依然として サイドパネル専用 となっています。

  • Capped Torus の Arc Angle: 回転角度パラメータのため、矢印ではなく将来的なダイヤル型ギズモ（Dial 3D）の実装待ち。
  • N-gon Prism の辺数（Sides）: 整数ステップ値のため、矢印ではなく将来的なステッパーボタン型ギズモの実装待ち。
  • Deform Stack の各項目（Elongate / Twist / Bend / Taper 等）: リスト構造およびモード依存スロットのため、ギズモ未対応。サイドパネルから数値調整してください。
  • 個別プリミティブ間のブール関係値: 2つのオブジェクト間の個別ブレンド半径などはパネル設定のみ。

② ギズモ矢印をドラッグしても見た目が変化しないケース

Smoothness（マゼンタ矢印）: 他のプリミティブと接触・重複していない「孤立したパーツ」では、矢印をドラッグして数値を変更しても、ブレンドする相手がいないため外観は変化しません（パーツが他と交差した瞬間にブレンドが反映されます）。

③ 多数ギズモ表示時の負荷（Phase G1スロットリング検証中）

1つのプリミティブに対して最大5〜6本のギズモが同時に出現するため、超高解像度（Ultra）かつ数百パーツのツリーでギズモを連続ドラッグすると、GPUの再計算キューが連続して走りFPSが低下することがあります。ギズモドラッグ時は解像度を Medium 以下にしておくことを推奨します。

④ 旧バージョンで保存されたファイルとのマテリアル互換性（V17.0.1）

V17.0.1の改善: Snapshot Mesh および Finalize (Bake All) 実行時にマテリアルが独立複製されるようになりました。
注意点: V17.0.0以前に作成・保存されたBlenderファイル の中に残っている既存のスナップショットメッシュは、過去の仕様（ライブツリーと同一マテリアルを共有）のままです。これらを独立化させたい場合は、最新のV17.0.1上で再度 Snapshot Mesh を実行してください。

6. トラブルシューティング Q&A（逆引きFAQ）

Q1. アドオン有効化時にエラー（ImportError / DLL load failed）が出る
Windows: Visual C++ 再頒布可能パッケージ（最新版）がインストールされているか確認してください。また、GPUディスプレイドライバを最新にアップデートしてください。
macOS: Apple Silicon Mac（M1〜M4）であることを確認し、上記「Gatekeeperブロック解除手順」を行ってください。
Linux: glibcのバージョンが2.31以上か、およびVulkanドライバが正常に動作しているか（vulkaninfo コマンド等）を確認してください。
Q2. 画面が真っ暗のまま進まない、または GPU: Updating のまま止まる
初回起動またはキャッシュ削除直後の Shader Compile中 です。特に内蔵GPUの場合は2〜3分待機してください。
5分以上待っても変化がない場合は、一度Blenderを閉じ、上記の手順で shader_cache.bin を削除してから再起動してください。
Q3. Transmission（透過ガラス）を設定したのに透けない
以下の3点を確認してください:
1. 3Dビューポートのシェーディングが 「マテリアルプレビュー」または「レンダー」 になっているか（ソリッド表示では透過しません）。
2. 6. Material セクションの Setup Material ボタンが押されているか。
3. Transmissionはプリミティブ個別ではなく、マテリアル全体で1つの共通値です。
Q4. 生成されたメッシュの角に細かいギザギザ・ジャギーが出る
3. Output & Quality の解像度を上げるか、4. Post-Process (Smoothing) の Enable Smoothing を ON にしてください。ラプラシアンスムージングにより微細な段差が滑らかに平滑化されます。
さらに 7. Finalize / Output の Fix Normals を押すと、数学的勾配による最高品質の法線が適用され、シェーディングが極めて美しくなります。
Q5. Finalizeした後に元のSDF編集に戻したい
Finalize (Bake All) を実行すると、元となったSDFプリミティブ群は 非表示の履歴コレクション（SDF_History_...） に自動退避されています。
完全に元のライブSDF状態へ復元したい場合は、Blenderのアウトライナーで履歴コレクションを表示状態に戻すか、作業途中で必ず Snapshot Mesh を使って節目節目でバックアップを残す運用を行ってください。
